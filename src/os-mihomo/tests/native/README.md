# Native checks

The VNET jail harness uses the installed package's genuine Core configuration
and BaseModel framework against a private `/conf/config.xml` generated by its
test case. `prepare.sh` selects only package-owned MVC PHP/XML files and PHP
modules, generates its own PHP configuration, and excludes host configuration,
credentials, bytecode and caches. It retains synthetic `util.inc`, configuration
revision, `configctl`, service, firewall templates and DNS templates. The adapted
harness executes the package's routing helper against genuine private PF and
FIBs, using its context parser with native jail interfaces. It checks that FIB0
stays native and capture rules target only the owned FIB. Its lifecycle
attestation does not prove host template generation or LAN packet forwarding.

The package lifecycle case distinguishes reinstall with a retained XML backup
from installation without one. It erases private application stores and verifies
that the retained backup restores administrative Stop, then removes only the
private XML's Mihomo backup node and erases the stores again to verify fresh
proxy-port defaults. Other XML nodes remain in place.

These adapters mean a script that calls a function the real OPNsense tree defines
elsewhere passes there and fails on a router. `setup_unbound.php` did exactly
that: it required `config.inc` alone, and `config.inc` reaches for
`shell_safe()` from `util.inc` when it stamps a configuration revision, so
every write failed the moment it was attempted on a real system.

`check-undefined.php` resolves every function each CLI entry point calls after
that entry point's own includes have run. Run it on the target:

```sh
php src/os-mihomo/tests/native/check-undefined.php
```

It needs the real tree and therefore cannot run in CI or on the build host.

The routing lifecycle regressions run locally with isolated manager stores and
mocked native commands. They exercise startup and rollback failures, independent
DNS recovery, runtime status, and migration to real-address DNS:

```sh
python3 -B -m unittest discover -s src/os-mihomo/tests -p test_routing_lifecycle.py -v
```

These PHP fixtures also run locally with PHP DOM and SimpleXML available:

```sh
php src/os-mihomo/tests/native/test-tun-rule-ownership.php
php src/os-mihomo/tests/native/test-routing-context.php
```

The ownership fixture invokes the unmodified integration CLI with
`OS_MIHOMO_ROOT` pointing to temporary XML and ownership journals. It verifies
legacy rule migration, pristine cleanup, and preservation of edited rules,
assignments and filter/NAT references. The context fixture supplies synthetic
interface data to check LAN selection and router/WAN exclusions. Neither check
exercises actual packet forwarding or the native Core configuration writer.

Run the Core writer and concurrency fixture as root on the matching OPNsense
target, using the installed helper when validating a package:

```sh
php src/os-mihomo/tests/native/test-integration-lock.php \
  /usr/local/opnsense/scripts/mihomo/setup_unbound.php
```

That fixture redirects Core configuration handles and saves to temporary XML.
Its cleanup seed contains the complete original plugin-owned rule and interface
baseline. Existing race, concurrent backup, scoped recovery, checksum and
repurposed ownership assertions remain active. It requires the genuine Core
framework and does not establish host PF routing or LAN connectivity.
