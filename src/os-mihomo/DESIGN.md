# Refactor contract and evidence

The owner selected proxy-only fresh installation, explicit combined TUN/DNS enablement, per-router DNS fallback (enabled by default), complete-subscription mode only, and an independent fork. Package output and catalog publication are separated from the source branch. Signing stays on the local router.

## One runtime manager

`mihomo.py` controls boot, UI actions, WAN events, CLI/cron updates, policy changes, and crash recovery. Configuration and policy files are root-only state under `/var/db/os-mihomo/`; none are package-owned. Configuration mutations and watchdog transitions share an advisory OS lock. A separate subscription lock prevents duplicate fetches; network waits release the state lock so crash recovery continues during a slow download. A downloaded response is discarded if URL/device settings changed; other policies and credentials use their latest values. Configd queues the update and returns immediately, with a separate status file recording job completion. The rc script delegates to the manager instead of having an independent restart implementation.

The state distinguishes administrator enablement, desired transparent policy, actual core state, and actual DNS integration. A successful update never silently starts an administratively stopped service. A WAN event never starts a stopped core. A crash fallback keeps the administrator's desired transparent policy while reporting DNS as inactive, so an explicit later Start can restore it.

Candidate YAML is structurally parsed with safe construction, duplicate explicit keys rejected, YAML 1.2 boolean handling, and recursive/deep data rejected. The generator retains provider proxy/group/rule data and owns local listeners, DNS enable/listen, dashboard credentials, and the TUN block. This deletes the old converter, extractor, node-name tokenizer, and template merger together.

The core validates a private candidate before any live state is replaced. A restart failure restores config, source, and settings, including the old secret, from private hard-link backups. File restoration proceeds even when DNS cleanup fails. A pending reload marker allows retries if configuration was committed but template or service reload failed. Unchanged integration skips unnecessary Unbound restarts. If the old core also fails, the files remain restored and the manager attempts direct DNS restoration; a restoration failure is reported explicitly with integration state retained for recovery. Validator output is captured and discarded because it can contain provider credentials.

Unbound integration uses OPNsense's native configuration lock and save/audit API. It snapshots original forwarding state, fake-IP rebinding protection, and pre-existing root DoT/forward entries. Existing root upstreams are disabled while the plugin root forwarder is active, avoiding duplicate root zones; disabling the integration restores them. Domain-specific upstreams remain active. DNS reload occurs through configd without deleting template output files. Interface/firewall ownership is recorded so uninstall removes only plugin-created entries.

## Subscription host source review

Reviewed Passwall-Sub-Panel `main` at commit `4c7b488a8b36ce98579a34624249ec68ac7d60fd`, without sending requests to the live subscription endpoint:

- [Client detection](https://github.com/KazuhaHub/Passwall-Sub-Panel/blob/4c7b488a8b36ce98579a34624249ec68ac7d60fd/internal/pkg/clientdetect/detect.go) lowercases UA and keywords and matches substrings. Families are evaluated in order; the first match wins. Whitelist mode requires a matched, enabled family.
- [Defaults](https://github.com/KazuhaHub/Passwall-Sub-Panel/blob/4c7b488a8b36ce98579a34624249ec68ac7d60fd/internal/adapters/sqlstore/settings_kv_repo.go) put `Clash / mihomo` first, with `clash`, `mihomo`, and `meta` keywords. The proposed UA matches `mihomo`. A dedicated `OPNsense-Mihomo/1` keyword must be ordered before this family to give the fleet separate permissions; a device-specific substring is only needed for per-device policy.
- [Request handling](https://github.com/KazuhaHub/Passwall-Sub-Panel/blob/4c7b488a8b36ce98579a34624249ec68ac7d60fd/internal/transport/http/handler/sub.go) advances blocked-client violations for a valid, accessible user, with a ten-minute deduplication window. Default threshold is 3, configurable globally and by group; reaching it suspends service only when automatic disabling is enabled. Initial blocked-client requests return 403; disabled service and invalid/unavailable tokens return opaque 404.
- [Counter persistence](https://github.com/KazuhaHub/Passwall-Sub-Panel/blob/4c7b488a8b36ce98579a34624249ec68ac7d60fd/internal/adapters/sqlstore/user_repo.go) increments the stored counter without time decay. [Service restoration](https://github.com/KazuhaHub/Passwall-Sub-Panel/blob/4c7b488a8b36ce98579a34624249ec68ac7d60fd/internal/service/user/user.go) clears it when restoring a blocked-client suspension. An allowed request does not reset it.

These are source-level conclusions; deployed panel settings and deployed revision were not probed. The UA's `/1` is a stable format version, independent of package version. Requests retry only timeout/5xx and never 4xx; even 408 and 429 stop immediately. Curl configuration holds the private URL outside process arguments, and no response body or URL is logged.

The package is produced by actual `pkg create` on FreeBSD 15, then its metadata and file ownership are inspected. The actual packaged core also starts successfully with an empty proxy-only config on isolated high ports, with TUN and DNS disabled. Configuration candidates generated from the existing provider config pass `mihomo -t` in both modes against the installed and bundled 1.19.28-vincent core; provider proxies, groups, and 9467 rules are unchanged in the observed snapshot. Validation does not bind TUN or install routes.

The repository is signed using the existing RSA key. Independent OpenSSL verification checks both catalog signatures over ASCII SHA-256; package SHA-256 matches the signed compatibility manifest. An isolated loopback HTTP server and separate pkg configuration/database/cache validate client access. The correct trust anchor exposes `os-mihomo 1.1.0`; a wrong key causes signature rejection and leaves no usable catalog. `pkg update` exit status alone is insufficient to detect that rejection on pkg 2.3.1.

The source validation and Pages deployment workflows also pass on GitHub Actions. Downloads from the public Pages endpoint pass independent signature and package-digest verification. The test router's isolated pkg client updates the published HTTPS catalog, queries `os-mihomo 1.1.0`, and fetches its package successfully with IPv4. The fetched SHA-256 is `87ce64c5aad735aa10cf4a8ce607aed6f1efe25eaa506f02227b00222fbdc469`. Production remains on `os-mihomo 1.0.2`.

No live package install, DNS switch, core restart, or TUN change is part of these isolated checks. End-to-end upgrade, actual failure timing, controller login, and LAN connectivity remain scheduled production checks; see [deployment](../../DEPLOYMENT.md).
